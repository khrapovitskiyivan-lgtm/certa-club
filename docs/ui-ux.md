# Certa: UI/UX-дизайн

Основа: исследование аналогов тремя независимыми агентами (18.10.2026) и решения, согласованные с основателями. Наблюдения агентов частично вторичные (часть сайтов не открылась), это помечено в исходных отчётах.

## Принципы

- Тихо, old money: никакого золота на чёрном, слов «эксклюзив», «элита», «платформа», «транзакция», «крипта» на видимых экранах.
- Доверие подаётся как стандарт, внизу и внутри, а не баннером («О клубе», футер), по образцу Subdial.
- На экране один смысл. Много воздуха, мелкий служебный текст, один крупный акцент.
- Анонимность по умолчанию: участник виден под псевдонимом; раскрытие зависит от способа расчёта и выбирается при открытии сделки.

## Визуальная система

| Токен | Значение |
|---|---|
| Фон (бумага) | #F3EFE7 |
| Текст (графит) | #1F1D1A |
| Вторичный текст | #6E675D |
| Линии | #D9D2C5 |
| Акцент (тёмно-зелёный) | #2F3A33 |
| Ошибка | #8A3B2E |

- Шрифты: Cormorant Garamond (название, заголовки, курсив для подписей) + Tenor Sans (основной и служебный текст, выбран основателем вместо Manrope). Оба с кириллицей.
- Служебные надписи: малый капс, разрядка 0.22em, 11-12px.
- Кнопка-действие: заливка акцентом, капс; вторичные действия: текст с подчёркиванием, которое рисуется слева направо.

## Правила моушена

1. Анимируются только opacity, transform, filter (blur), letter-spacing, clip-path.
2. Одна кривая на весь сайт: cubic-bezier(0.22, 1, 0.36, 1).
3. Вход 400-600 мс с задержкой 80 мс против мигания; выход быстрее, около 250 мс.
4. Без отскоков, вращений, параллакса больше 20px. В каждый момент движется одно событие.
5. Интро нельзя ждать: клик, клавиша или прокрутка доводят его до финала. Повторный визит в сессии: интро в 3 раза быстрее.
6. Контент, скрытый до наведения, на тач-устройствах показывается после интро; при prefers-reduced-motion всё статично.
7. Главное действие (вход по приглашению) не прячется полностью: оно тихое (opacity 0.32) и проявляется при наведении.

## Главная (сделано)

Только название и «Вход по приглашению». Таймлайн: линия растёт из центра (0-0.8 с), CERTA проявляется по буквам из размытия со сдвигом к центру (с 0.8 с, шаг 0.2 с, 2.2 с на букву), вход (4 с). Перевод названия на главной не показывается, он уходит в описание клуба. Подпись «Редкие вещи. Проверенные люди.» видна только при наведении на название. Клик по входу раскрывает поле кода; неверный код даёт нейтральное сообщение без подробностей.

## Вступление (сделано)

Модель: вход только по приглашению. Участник рекомендует знакомого (имя и контакт), экспертный совет одобряет, кандидату уходит личная ссылка: одноразовая, со сроком, код хранится только хешем.

Путь по ссылке, три шага с индикатором:
1. **О клубе**: что такое Certa, как устроено, конфиденциальность, что дальше; перевод названия (certa, лат. надёжная). Тексты черновые, правят основатели.
2. **О вас**: имя, почта, телефон, город, род занятий, необязательное «чем поделиться» (с предупреждением не писать счета и активы), псевдоним, пароль от 12 символов, согласие с правилами и соглашением об ЭП. Об активах не спрашиваем.
3. **Верификация** (KYC при вступлении, по стандарту частного банковского обслуживания): лично через провайдера (провайдер не выбран, ссылку присылает куратор) или через агента (банк, семейный офис, представитель; контакт агента, клуб связывается сам).

После отправки: «Верификация на рассмотрении», доступ к клубу после подтверждения советом. Использованная или просроченная ссылка: «Приглашение недействительно» с причиной. Слово «отказ» не используется нигде.

## Витрина (следующий этап)

- Две ленты: «Предложения клуба» и «Ищут в клубе».
- Запрос на покупку публичен внутри клуба: псевдоним, референс/описание, год, бюджетный коридор; личность скрыта. На запросе кнопка «Есть у меня», открывающая приватный диалог (Subdial).
- Лот «по запросу»: вместо цены «Запросить цену», но сделка всё равно идёт по этапам Certa. Так закрывается дыра Chrono24, где price on request выпадает из защиты.
- Оффер с мягким предупреждением о заниженной цене; продавец может отключить офферы (Chrono24).
- В карточке лота два пути: «Купить / запросить» и «Обсудить с куратором» (Sotheby's: Buy Now против private sales).
- Бейдж в два слоя: «предпроверка по фото» и «экспертиза Certa» с сертификатом (Bezel, The Cultt). Рядом с ценой экспертизы прямо: при провале вещь не передаётся, деньги возвращаются.
- «Тихий» лот (по итогам интервью с голосом клиента): без фото, виден только тем, кого подобрал куратор.
- Лот можно снять в любой момент; экспертиза не обязательна для публикации.

## Сделка (следующий этап)

- Одинаковые этапы у обеих сторон: согласование, экспертиза, договор, расчёт, передача, подтверждение, закрытие. Видно, где сейчас вещь (Oskelly).
- При выборе способа расчёта сразу показывается, что увидит контрагент (степень анонимности).
- Ограниченное окно претензии после передачи, кнопка прямо в карточке сделки (Bezel, Chrono24).
- Спор замораживает сделку; медиатор клуба даёт заключение, исполнение через агента расчёта.

## Открытые вопросы

- Подпись под названием окончательно не выбрана (сейчас «Редкие вещи. Проверенные люди.»).
- Сделано: вход (почта, пароль, второй фактор TOTP с QR при первом входе), кабинет совета (заявки на верификацию, подтверждение, приглашения с одноразовым показом ссылки, список участников и приглашений), страница участника. Первый член совета назначается командой `npm run council -- почта`.
- Вход участника (по рекомендации эксперта): одно поле на главной принимает код приглашения или почту. На почту ответ всегда одинаковый («Если вы участник клуба, ссылка отправлена»), не быстрее 0,9 с; письмо со ссылкой (15 минут, одноразовая, гасится только кнопкой) уходит только участнику; дальше пароль и код с телефона. Сессия 30 дней, вошедший участник с главной сразу попадает в клуб. Почтовый сервис не выбран: письма пишутся в .data/outbox.log.
- Не сделано: кнопка «Рекомендовать» у участника, восстановление доступа при потере телефона, вход по отпечатку или лицу (passkey).
- Хранилище временное (файл); перенос в Postgres после выбора хостинга и юрисдикции.
- Ограничения попыток (вход, код второго фактора, код приглашения) хранятся в памяти процесса: при нескольких серверах вынести в общее хранилище.
